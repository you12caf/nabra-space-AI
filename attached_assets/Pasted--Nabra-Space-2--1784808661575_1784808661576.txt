## الموجه 1 — الأساس: البنية + المصادقة + قاعدة البيانات (وظيفة أولاً)

**ماذا يفعل:** يبني الهيكل التقني، يربط Supabase، وينشئ كل الجداول — بأقل تصميم ممكن الآن، فقط واجهة نظيفة وبسيطة تعمل.

**النتيجة المتوقعة:** مستخدم يدخل بـ Google، يُنشأ له رصيد 500 حرف تلقائيًا، ولو دخل بإيميل `youcef20226@gmail.com` يصبح أدمين تلقائيًا بدون أي خطوة يدوية.

```
ابنِ مشروع SaaS باسم "Nabra Space" بالستاك التالي (إجباري لتوافق Cloudflare لاحقًا):
- Frontend: React + Vite + TailwindCSS + shadcn/ui (تصميم بسيط ونظيف الآن فقط، بدون حركات معقدة — الأولوية للوظائف)
- Backend: Hono (متوافق مع Cloudflare Workers)، لا تستخدم Express ولا أي Node API غير متوافق مع Workers.

هذه المرحلة أولوية قصوى: **كل شيء يجب أن يعمل فعليًا وتختبره بنفسك قبل الانتقال لأي تحسين بصري**. لا تصرف وقتًا في تفاصيل تصميم دقيقة الآن.

اربط Supabase عبر متغيرات البيئة (موجودة في Secrets): SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY
فعّل تسجيل الدخول عبر Google OAuth فقط عبر Supabase Auth.

أنشئ الجداول التالية في Supabase مع RLS مفعّل على الجميع (كل مستخدم يرى بياناته فقط، الأدمين يرى كل شيء):

users_profile: user_id, email, credits_balance (integer), is_admin (boolean), full_name, avatar_url, created_at
generation_history: id, user_id, text_input, character_count, blocks_json (jsonb — يحفظ كل البلوكات ونبراتها), audio_url, status, created_at
transactions: id, user_id, amount_usd, characters_granted, dodo_payment_id, status (pending/completed/failed), created_at
affiliates: user_id, referral_code (unique), commission_rate (default 0.15), total_clicks, total_signups, total_conversions, pending_balance, available_balance, status
referral_attributions: id, referred_user_id (unique), affiliate_user_id, attributed_at, first_paid_conversion_at
promo_codes: id, code (unique), characters_granted (integer), max_total_uses, max_uses_per_user (default 1), current_uses, expires_at (nullable), linked_affiliate_id (nullable), is_active
promo_code_redemptions: id, promo_code_id, user_id, redeemed_at

اكتب Trigger على auth.users (AFTER INSERT) ينشئ تلقائيًا صفًا في users_profile وصفًا في affiliates لكل مستخدم جديد. منطق الرصيد الابتدائي والأدمين داخل نفس الـ trigger:
- credits_balance = 500 (رصيد مجاني تلقائي لكل حساب جديد، بدون أي شرط دفع)
- is_admin = true فقط إذا كان NEW.email = 'youcef20226@gmail.com'، وإلا false لكل الحسابات الأخرى

⚠️ قاعدة مهمة تنطبق على كل الموجهات القادمة: لا تعرض أبدًا أي سعر أو قيمة بالدينار الجزائري (DZD) في أي مكان بالواجهة. الأسعار بالدولار فقط، دائمًا.

النتيجة المطلوبة: أسجل دخول بحساب Google عادي → أتحقق في قاعدة البيانات أن رصيدي 500 حرف بالضبط وis_admin=false. أسجل دخول (أو أطلب منك محاكاة الفحص) بإيميل youcef20226@gmail.com → أتحقق أن is_admin=true تلقائيًا. اختبر هذا فعليًا بنفسك.

## الموجه 2 — محرك توليد الصوت بالبلوكات (نفس آلية الـ MVP المثبتة)

**ماذا يفعل:** يبني محرر البلوكات وباك إند التوليد بنفس الآلية المضبوطة التي أثبتت نجاحها: بلوكات نص+نبرة → نص واحد مجمّع → استدعاء Gemini واحد → صوت واحد متصل.

**النتيجة المتوقعة:** أكتب عدة بلوكات بنبرات مختلفة، أضغط توليد، يخرج لي ملف صوتي واحد متصل ينتقل بين النبرات، يشتغل فعليًا في المتصفح.

```
ابنِ محرك توليد الصوت بهذه الآلية بالضبط — لا تنحرف عنها، هي مُثبَتة ومُختبرة:

### الواجهة (صفحة /generate):
- الحالة: مصفوفة blocks، كل عنصر { tone: string, text: string }، تبدأ بعنصر واحد { tone: "Calm", text: "" }.
- لكل بلوك: قائمة اختيار Tone (قيم ثابتة فقط، بدون "تخصيص حر"):
  Friendly, Relieved, Excited, Curious, Satisfied, Calm, Serious, Energetic
  (اعرضها بالعربية: ودود، مرتاح، متحمس، فضولي، راضٍ، هادئ، جاد، حيوي)
- مربع نص لكل بلوك + عداد أحرف + زر حذف (معطّل عند بلوك واحد متبقٍ).
- زر "+ إضافة بلوك".
- **عداد رصيد ظاهر دائمًا في أعلى الصفحة** (وفي الحقيقة في كل صفحات لوحة التحكم — ضعه في الـ layout المشترك وليس فقط هنا): "رصيدك: X حرف"، يُحدَّث فوريًا بعد كل عملية.
- شريط سفلي: مجموع أحرف كل البلوكات + زر توليد. الزر معطّل إذا: أي بلوك فارغ، أو مجموع الأحرف > الرصيد المتاح، أو التوليد جارٍ.
- إذا الرصيد غير كافٍ: رسالة واضحة "رصيدك غير كافٍ (تحتاج X حرف، لديك Y)" + رابط لصفحة الشحن. لا يُرسَل أي طلب لـ Gemini في هذه الحالة.
- بعد الضغط توليد: أنشئ job بحالة processing، استطلع حالته كل 2 ثانية حتى completed/failed، اعرض مؤشر تحميل واضح.
- عند الاكتمال: مشغّل صوت واحد لكل الناتج + رسالة نجاح. عند الفشل: رسالة خطأ واضحة، ولا خصم أي رصيد.

### الباك إند — الآلية الدقيقة (إجبارية):

1. اجمع كل البلوكات في نص واحد بصيغة:
   [Tone1]
   نص البلوك الأول
   [Tone2]
   نص البلوك الثاني
   (سطر بالتون بين قوسين مربعين، ثم النص، لكل بلوك بالترتيب)

2. أضف قبل هذا النص system instructions ثابتة بالإنجليزية بالضبط (مدمجة داخل نفس الـ prompt لأن نماذج TTS لا تدعم systemInstruction منفصلة):

You are a professional Algerian voice actor.
Environment: A professional closed recording studio, absolute silence, high acoustic isolation, no echoes.
Dialect Lock: You must strictly read and pronounce the text in authentic Algerian Darja (Algerian Dialect) 100%. Under no circumstances are you allowed to use Modern Standard Arabic (Fusha) pronunciation or tone.
Emotion Guidelines: You will receive text blocks prefixed with emotion tags in square brackets like [Friendly] or [Excited]. You must adapt your voice pitch, speed, and emotional tone instantly based on these tags.

3. استدعاء واحد فقط لـ Gemini TTS:
   POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-preview-tts:generateContent?key=GEMINI_API_KEY
   body: { contents: [{ role: "user", parts: [{ text: <النص الكامل> }] }], generationConfig: { responseModalities: ["AUDIO"], speechConfig: { voiceConfig: { prebuiltVoiceConfig: { voiceName: "Aoede" } } } } }
   timeout: 120 ثانية. 3 محاولات إعادة (exponential backoff) عند الفشل المؤقت.

4. ⚠️ إجباري: Gemini يرجّع PCM خام بدون هيدر. اكتب دالة تحوّله لـ WAV صالح (هيدر RIFF/WAVE 44 بايت، استخرج sample rate من الـ mimeType مثل "audio/L16;rate=24000"، mono، 16-bit). بدون هذا الصوت لن يعمل في المتصفح إطلاقًا.

5. ارفع WAV الناتج لـ Supabase Storage (bucket خاص "generated-audio")، احفظ المسار في audio_url بجدول generation_history.
6. أنشئ endpoint مصادَق GET /api/generations/:id/stream يبث الصوت فقط لصاحبه.
7. اخصم الرصيد (credits_balance -= مجموع الأحرف) فقط بعد نجاح الرفع الكامل. لا خصم عند أي فشل جزئي.
8. أضف صفحة /history تعرض كل التوليدات (نص، تاريخ، عدد الأحرف، حالة) مع زر تشغيل يفتح الصوت المحفوظ.

النتيجة المطلوبة: بلوكين بنبرتين مختلفتين (Calm ثم Excited)، ولّد، تأكد أنه صوت واحد متصل ينتقل بين النبرتين ويعمل فعليًا. جرّب أيضًا توليدًا يتجاوز رصيدك المتاح وتأكد أنه يُمنَع برسالة واضحة قبل إرسال أي طلب لـ Gemini.
```

## الموجه 3 — الدفع: Dodo Payments بالباقات الثلاث (دولار فقط)

**ماذا يفعل:** يربط Dodo Payments بالباقات النهائية المتفق عليها، تأكيد عبر Webhook فقط.

**النتيجة المتوقعة:** شراء أي باقة يضيف الرصيد الصحيح تلقائيًا، بدون أي ذكر للدينار في أي مكان.

```
ادمج Dodo Payments (المصدر الرسمي: docs.dodopayments.com/developer-resources/dodo-payments-sdks، حزمة npm "dodopayments") بهذه الباقات بالضبط:

الباقة 1 — "الانطلاقة": 1.00$ → 6,000 حرف
الباقة 2 — "المحترف" (وسم "الأكثر طلبًا"): 5.00$ → 40,000 حرف
الباقة 3 — "المتجر / الوكالة" (وسم "أفضل قيمة"): 10.00$ → 100,000 حرف

اعرض الأسعار بالدولار فقط، بدون أي إشارة للدينار الجزائري في أي مكان بالموقع (صفحة التسعير، الشحن، الفواتير، كل مكان).

مفتاح DODO_API_KEY من السيرفر فقط. أنشئ Checkout Session لكل باقة عبر الباك إند.

⚠️ قاعدة أمان إجبارية: لا تُضِف أي رصيد بناءً على استجابة نجاح من المتصفح وحدها. الإضافة الفعلية تحدث فقط عند استقبال Webhook موقّع ومتحقق منه (HMAC-SHA256 عبر DODO_WEBHOOK_SECRET). سجّل كل عملية في جدول transactions بحالتها.

النتيجة المطلوبة: أدفع (Test Mode) لأي باقة، أتحقق أن الرصيد أُضيف فقط بعد استقبال الـ Webhook، والعداد أعلى الصفحة تحدّث فورًا.
```

## الموجه 4 — الهدايا والإحالات: العمولة + الأكواد الترويجية (رفع المستوى)

**ماذا يفعل:** يبني نظامين مدمجين في صفحة واحدة واضحة "الهدايا والإحالات": الإحالة التلقائية بعمولة، والأكواد الترويجية القابلة للاستبدال مباشرة بدون أي دفع.

**النتيجة المتوقعة:** صفحة واحدة قوية فيها رابط الإحالة + إحصائياته + خانة استبدال كود تضيف حروفًا فورًا لأي مستخدم، مدفوعًا كان أو لا.

```
ابنِ صفحة /gifts ("الهدايا والإحالات") تحتوي قسمين واضحين بتصميم نظيف واحترافي (هذه الصفحة تستحق اهتمامًا أعلى من بقية الواجهة، لأنها محرك النمو الأساسي للمنصة):

### القسم 1 — رابط الإحالة:
- رابط فريد (nabra.space/?ref=CODE) + زر نسخ سريع بارز.
- 3 إحصائيات واضحة بأرقام كبيرة: عدد الزيارات (clicks)، عدد التسجيلات (signups)، عدد التحويلات المدفوعة (conversions).
- رصيدان منفصلان بصريًا: "معلّق" (pending، بلون مختلف) و"متاح للسحب" (available)، مع ملاحظة "10 أيام انتظار قبل أن يصبح الرصيد متاحًا".

منطق الإحالة في الباك إند:
- عند زيارة الرابط: كوكيز صالحة 30 يومًا تحفظ referral_code.
- عند التسجيل: POST /api/affiliate/attribute يربط referred_user_id بـ affiliate_user_id. إذا كان نفس المستخدم (self-referral)، ارفض بصمت (200 OK بدون أي تأثير).
- العمولة (commission_rate الخاص بالمسوّق، افتراضيًا 15%) تُحتسب فقط بعد أول عملية شراء حقيقية ناجحة (وليس عند التسجيل).
- تُوضع في pending_balance، وبعد 10 أيام (يمكن تنفيذها بفحص عند تحميل الصفحة: أي عمولة أُضيفت منذ أكثر من 10 أيام تُنقل تلقائيًا من pending إلى available)، تصبح available_balance.

### القسم 2 — استبدال كود هدية:
- خانة نص واحدة + زر "استبدال" — بسيطة وواضحة، بلا أي حقول إضافية.
- ⚠️ قاعدة جوهرية: استبدال الكود **لا يتطلب أي عملية دفع سابقة أو رصيد كافٍ أو أي شرط آخر** — أي مستخدم مسجَّل (حتى لو لم يدفع قط) يقدر يدخل كودًا صالحًا ويحصل فورًا على الحروف المذكورة فيه مباشرة، مضافة لرصيده الحالي.
- عند النجاح: رسالة واضحة "🎉 تمت إضافة X حرف لرصيدك!" + تحديث فوري للعداد أعلى الصفحة.
- عند الفشل (كود منتهي/مستهلك بالكامل/مستخدم من قبل لنفس الحساب/غير موجود): رسالة خطأ محددة تشرح السبب بالضبط.

منطق الباك إند لاستبدال الكود (POST /api/promo-codes/redeem):
1. تحقق أن الكود موجود وis_active=true وexpires_at لم يمضِ (أو فارغ).
2. تحقق current_uses < max_total_uses.
3. تحقق أن هذا المستخدم لم يستخدم هذا الكود من قبل أكثر من max_uses_per_user مرة (افتراضيًا 1).
4. إذا كل الشروط محققة: أضف characters_granted لرصيد المستخدم مباشرة، سجّل في promo_code_redemptions، زد current_uses بواحد.
5. كل هذا داخل معاملة قاعدة بيانات واحدة (transaction) لمنع أي تلاعب بالتزامن (race condition لو استُخدم الكود من عدة أجهزة بنفس اللحظة).

### لوحة الأدمين لإدارة الأكواد (جزء من هذا الموجه أيضًا):
نموذج إنشاء كود جديد بحقول: الكود (إدخال يدوي أو توليد عشوائي بزر)، عدد الحروف الممنوحة، الحد الأقصى للاستخدام الكلي، الحد لكل مستخدم (افتراضي 1)، تاريخ انتهاء اختياري، ربط اختياري بمسوّق موجود (لحملات المؤثرين — عندما يُستخدم الكود، تُسجَّل إحالة تلقائيًا لذلك المسوّق أيضًا، مثل نظام الإحالة العادي).
جدول يعرض كل الأكواد: الكود، الحروف، الاستخدام الحالي/الأقصى، الانتهاء، الحالة، مع أزرار تفعيل/إيقاف/حذف.

النتيجة المطلوبة: أنشئ كودًا من لوحة الأدمين بقيمة 200 حرف، افتح حساب مستخدم آخر (بدون أي رصيد مدفوع)، استبدل الكود من صفحة /gifts، تأكد أن رصيده زاد بـ200 حرف فورًا. جرّب أيضًا رابط إحالة من متصفح آخر وتأكد أن الإحصائيات تحدّثت.
```

## الموجه 5 — لوحة الأدمين الاحترافية (رفع المستوى للأقصى)

**ماذا يفعل:** يبني لوحة تحكم أدمين كاملة وقوية فعليًا، بخمس أقسام واضحة، بيانات حقيقية من قاعدة البيانات، وأدوات تحكم فعلية وليس فقط عرضًا.

**النتيجة المتوقعة:** لوحة أدمين تعطي رؤية مالية وتشغيلية كاملة للمنصة بضغطة واحدة، وتسمح بالتحكم الفعلي بالمستخدمين والأكواد والمسوّقين.

```
ابنِ صفحة /admin (مرئية فقط إذا profile.is_admin === true، وإلا إعادة توجيه فورية) بخمسة تبويبات (tabs)، كل واحد يجب أن يعمل فعليًا بأرقام حقيقية من قاعدة البيانات — لا بيانات وهمية أو عناصر واجهة فقط بدون منطق خلفها:

### تبويب 1 — نظرة عامة (Overview):
بطاقات إحصائية كبيرة وواضحة:
- إجمالي المستخدمين (+ نسبة نمو مقارنة بالأسبوع الماضي)
- إجمالي الإيرادات (كل الوقت) + إيرادات هذا الشهر
- إجمالي الحروف المولَّدة على المنصة كلها
- نسبة نجاح التوليد (توليدات completed ÷ إجمالي المحاولات × 100)
رسم بياني خطي بسيط لنمو عدد المستخدمين آخر 30 يوم (استخدم مكتبة recharts).
جدول مصغّر: أحدث 10 معاملات دفع (المستخدم، الباقة، المبلغ، الحالة، التاريخ).
قائمة مصغّرة: أفضل 5 مسوّقين هذا الشهر حسب عدد التحويلات.

### تبويب 2 — المستخدمون:
جدول كامل بكل المستخدمين، بحث فوري بالبريد، أعمدة: البريد، تاريخ التسجيل، الرصيد الحالي، عدد التوليدات، إجمالي الإنفاق، هل أدمين (badge)، الحالة.
لكل صف: زر "تعديل الرصيد يدويًا" (مودال يدخل فيه الأدمين قيمة جديدة أو يضيف/يخصم كمية — مفيد لخدمة العملاء)، وزر حظر/رفع حظر الحساب.

### تبويب 3 — المعاملات المالية:
كل المعاملات (transactions) بفلترة حسب الحالة (pending/completed/failed) والتاريخ. كل صف يعرض: المستخدم، الباقة، المبلغ بالدولار، الحروف الممنوحة، معرف Dodo، الحالة، التاريخ.

### تبويب 4 — الأكواد الترويجية:
(كما بُني في الموجه 4 — تأكد أنه مدمج هنا كتبويب في نفس لوحة الأدمين، وليس صفحة منفصلة).
